Privacy policy

Personal Drive Backup is a personal backup automation operated by eliranpv11 for the owner's own files and Google account. It is not offered as a service to other users.

1. Data accessed and used

The local tool reads files selected for backup, including their contents, names, paths, sizes, and modification times. Restic encrypts file contents and backup metadata before storing them in a backup repository.

Through rclone, the tool uses Google Drive file contents and metadata needed to create, list, read, verify, and restore its backup repository. It may obtain storage quota information when checking the destination. Its full Drive OAuth scope technically permits access to other Drive files, although the backup automation is configured to target its designated repository.

Google OAuth access and refresh tokens allow the tool to access Drive without a new sign-in for every scheduled backup. The tool does not collect the Google account password.

2. Where data is stored

Encrypted backups are stored on the owner's local storage and in the owner's Google Drive. Google receives the encrypted repository data and the Drive requests required to store and retrieve it. Local diagnostic logs can include file paths, error messages, backup identifiers, and run statistics.

OAuth credentials and tokens are stored locally in the rclone configuration, protected by operating-system file permissions. The Restic password is stored locally using Windows protection tied to the owner's user account and is made available to the running backup process. These secrets are not published on this website.

3. Sharing and purpose limits

The tool uses Google user data only for the owner's backup, verification, and recovery operations. The operator does not sell that data, use it for advertising, or use it to train AI models. Backup contents and credentials are not uploaded to this public documentation repository.

Google processes Drive storage and API activity under its own applicable terms and privacy policy. The application has no separate hosted backend that receives the owner's backup data.

4. Retention and deletion

Backups remain until the owner deliberately removes snapshots or repositories. During the current migration setup, automatic backup retention deletion is disabled. Deleting an original file does not automatically remove copies from existing backup snapshots.

The owner controls deletion of local backup data, local logs, and cloud repositories. Google Drive trash and retention behavior may affect when a deleted cloud file is permanently removed.

5. Revoking access

The owner can revoke the application's authorization in Google Account connections and disable the local scheduled task. Revocation prevents future authorized Drive operations; it does not delete existing local or cloud backups. The owner may separately remove local OAuth credentials after disabling the tool.

6. This website

These static pages contain no analytics scripts, advertising, forms, or application cookies. They do not collect Google tokens or backup files. GitHub Pages hosts the site and may process technical request information, such as IP addresses, under the GitHub privacy statement. Following an external link is subject to that site's policies.

7. Changes and contact

This page will be updated if the documented data practices change. Questions can be sent to the maintainer through the documentation repository. Public issues must not contain private files, passwords, authorization codes, or tokens.
